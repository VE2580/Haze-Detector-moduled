## 2. 数据流

### 定位流程
```
1. 用户打开页面
   ↓
2. 前端加载百度地图 JS SDK
   ↓
3. 通过百度地图定位组件获取坐标与城市信息
   ↓
4. 定位成功后前端将城市信息发送到后端 POST /api/location
   ↓
5. 后端保存定位结果到内存存储，并返回城市信息
   ↓
6. 若百度地图加载失败或定位失败，前端切换到手动城市选择
```

### 天气查询流程
```
1. 前端获取到城市名称
   ↓
2. 前端请求 GET /api/weather?city=城市名
   ↓
3. 后端检查内存缓存中的天气数据是否过期
   ↓
4. 如果缓存过期，调用和风天气 API 更新
   ↓
5. 返回天气数据：温度、湿度、AQI、污染物等
   ↓
6. 前端渲染展示页面
```

## 3. API 接口设计

### 后端 API 端点

#### 1. 定位接口
```
POST /api/location
请求体：
{
  "lat": 39.9042,
  "lon": 116.4074
}

响应：
{
  "code": 0,
  "message": "success",
  "data": {
    "city": "北京市",
    "district": "朝阳区",
    "address": "..."
  }
}
```

#### 2. 天气接口
```
GET /api/weather?city=北京市

响应：
{
  "code": 0,
  "message": "success",
  "data": {
    "city": "北京市",
    "temp": 25,
    "humidity": 65,
    "weather": "晴",
    "wind_speed": 3,
    "aqi": 85,
    "aqi_level": "良",
    "pollutants": {
      "PM2.5": 35,
      "PM10": 52,
      "O3": 120,
      "NO2": 45,
      "SO2": 12,
      "CO": 0.8
    },
    "update_time": "2026-05-06 14:30:00"
  }
}
```

#### 3. AQI 接口
```
GET /api/aqi?city=北京市

响应：
{
  "code": 0,
  "message": "success",
  "data": {
    "city": "北京市",
    "aqi": 85,
    "level": "良",
    "primary_pollutant": "PM2.5",
    "advice": "空气质量良好，适宜户外活动",
    "timestamp": 1620316200
  }
}
```

## 5. 数据缓存策略

- 天气与 AQI 数据使用内存缓存，默认缓存 **1 小时**，定位或手动切换城市时可强制刷新
- 定位数据实时保存到内存存储
- 趋势图使用和风逐小时预报数据，按城市实时请求

## 6. 响应式设计

- 支持 **手机（320px - 768px）**
- 支持 **平板（768px - 1024px）**
- 支持 **桌面（1024px+）**

使用 CSS Media Queries 和 Flexbox/Grid 布局

## 7. 安全考虑

- API Key 存储在后端环境变量中
- 前端不直接暴露 API Key
- 实现请求频率限制（Rate Limiting）
- CORS 跨域配置
