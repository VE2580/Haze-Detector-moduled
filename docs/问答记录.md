# 雾霾探测系统问答记录

> 记录和整理开发过程中已经问过的问题，以及对应的标准回答，方便后续答辩复习。

## 1. 这个项目已经开发结束了吗？

**问：** 这个项目已经开发结束了吗？

**答：** 功能层面基本已经完成，定位、天气、AQI、逐小时趋势图、手动城市切换、真实百度/和风数据接入都已经落地。交付层面还有正式部署、性能压测和更系统的自动化测试没有完全收口，所以更准确地说是“核心功能完成，项目收尾未完全结束”。

## 2. 项目结构为什么和实际的不太一样？

**问：** 这个项目结构为啥和实际的不太一样？

**答：** 因为 README 里有一部分是早期模板内容，后续开发过程中代码结构变了，但文档没有同步更新。比如文档里写了 routes、controllers、config 目录，但实际项目是单体后端 `server.js`；文档里写了 Chart.js，但实际只用了 ECharts；文档里写了 `config.example.js`，实际用的是 `.env.example`。这属于文档滞后，不是项目异常。

## 3. 后端主要业务是不是都写在 server.js 里？

**问：** 后端的主要业务就写在 `server.js` 里吗？

**答：** 是的。当前后端是一个实验型单体服务，路由、第三方 API 调用、缓存、统一返回格式都集中在 `server.js` 中。对这个规模的项目来说，这样更简单直接，便于老师理解。后续如果项目变大，才适合拆分成 routes、controllers、services 等层。

## 4. package.json、package-lock.json 是什么？

**问：** `package.json`、`package-lock.json` 是什么，为什么要提交？

**答：** `package.json` 像项目说明书，记录项目名称、脚本、依赖列表，属于人工维护的配置文件；`package-lock.json` 是 npm 自动生成的依赖锁定文件，用来固定每个依赖的精确版本和依赖树，防止不同机器装出不一样的结果。两个文件都应该提交，`node_modules` 不提交。

## 5. package.json 和 package-lock.json 是自动生成的吗？

**问：** 这俩文件是自动生成的吗？

**答：** `package.json` 通常是 `npm init` 先生成基础模板，然后再人工修改；`package-lock.json` 基本上是 npm 在安装依赖时自动生成的。也就是说，`package.json` 是半自动，`package-lock.json` 是自动生成。

## 6. .env 每一项是什么意思？

**问：** `env` 每条是啥意思？

**答：**
- `PORT`：后端监听端口
- `BAIDU_MAP_API_KEY`：百度地图 Key，用来调用百度地图相关能力
- `BAIDU_MAP_REFERER`：百度地图接口来源页地址，用于白名单校验
- `QWEATHER_API_KEY`：和风天气 Key，用来请求天气和空气质量数据
- `QWEATHER_API_HOST`：和风天气 API 主机地址
- `CACHE_TTL_WEATHER`：天气缓存时间，单位秒
- `CACHE_TTL_AQI`：AQI 缓存时间，单位秒
- `CORS_ORIGIN`：允许跨域访问的前端来源地址

## 7. env 文件要不要提交？

**问：** 锁定依赖脚本也不提交吗？

**答：** 这里需要区分两种文件：
- `package-lock.json` 要提交，因为它是依赖锁定文件
- `.env` 不提交，因为里面通常是真实 Key 和本地配置，应该放在 `.gitignore` 里
- `backend/.env.example` 要提交，用来告诉别人需要哪些环境变量

## 8. 数据是怎么存到缓存里的，路由是怎么走的？

**问：** 具体来说数据是怎么存到缓存里的，路由是怎么走的？

**答：**
- 后端先读取 `.env` 配置，然后初始化 `locationStore` 和 `weatherCache` 两个内存对象
- `/api/location` 会把定位结果存到 `locationStore[经纬度]`
- `/api/weather` 和 `/api/aqi` 会先检查 `weatherCache[城市名]`
- 如果缓存没过期，就直接返回缓存，不再请求和风
- 如果缓存过期或手动强制刷新，就重新请求和风天气和空气质量接口，然后写回 `weatherCache`
- `/api/trend` 直接请求和风逐小时预报，不走天气缓存

## 9. 天气、AQI、趋势图这些接口分别做什么？

**问：** 路由具体是怎么走的？

**答：**
- `/api/location`：保存定位信息，返回城市、区县、地址
- `/api/weather`：按城市返回实时天气信息
- `/api/aqi`：按城市返回空气质量详情
- `/api/trend`：按城市返回逐小时趋势数据
- `/health`：健康检查接口，确认服务是否运行

## 10. 项目核心功能做完了吗？

**问：** 文档里没收口，那实际上做完了吗？

**答：** 代码层面的核心功能已经完成，包括真实数据接入、定位、天气、AQI、趋势图、手动城市切换和响应式适配。文档里之所以还会出现未完成项，主要是因为还有部署和完整自动化测试没有做完。也就是说，“核心功能完成，项目收尾未完全结束”。

## 11. 为什么手机 http 下定位会有问题？

**问：** 能不能让手机 http 也能定位？

**答：** 项目后来改成了百度地图 JS SDK 定位，优点是能在浏览器端拿到城市信息，并且能给手机和电脑做统一处理；但它不是对所有 http 场景都百分百可用，浏览器或网络环境仍可能限制定位。若百度脚本加载失败或定位失败，就切换到手动城市选择兜底。

## 12. README、DESIGN、API 文档为什么要同步改？

**问：** 为什么要把文档也改？

**答：** 因为老师答辩时通常会先看文档，再追问代码实现。如果文档和代码不一致，就容易答不上来。所以需要把 README、设计文档、API 文档统一成真实项目状态，避免“文档写了但代码没有”或者“代码有了但文档没写”的问题。

## 复习建议

如果答辩时间很短，优先记住下面这几个核心点：

1. 项目是一个基于 Node.js + Express + 百度地图 + 和风天气的雾霾探测系统。
2. 前端负责展示和交互，后端负责统一调 API、做缓存和返回标准格式。
3. 数据流是“前端拿城市 -> 后端查缓存 -> 缓存没命中再调第三方 API”。
4. 项目已经完成核心功能，未完成的是部署和更系统的自动化测试。
5. `package.json`、`package-lock.json`、`.env` 的作用和是否提交要分清楚。
